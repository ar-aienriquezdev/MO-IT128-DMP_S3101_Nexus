## 1) Purpose

Milestone 2 converts Milestone 1’s cleaned and feature-engineered customer dataset into **data-driven customer segments** using **unsupervised clustering**.

Goals:
- Select a **clean, non-redundant** feature set for clustering
- Reduce multicollinearity and noise using **PCA**
- Apply **K-Means** clustering and determine an appropriate **k**
- Generate **cluster labels**, **profiles**, and **business-friendly segment names**
- Validate that clusters are meaningfully different using **statistical tests**

## 3) Methodology (Milestone 2)

### 3.1 Feature Selection (redundancy-aware)
We trimmed features to avoid redundancy and reduce multicollinearity. Examples:
- Avoided keeping multiple variants of the same metric family (e.g., min/max/mean sets)
- Kept representative, interpretable signals (e.g., mean-based experience measures)
- Reduced overlapping behavioral buckets where applicable (e.g., time-of-day shares)

**Why:** Redundant features can overweight the same signal in distance-based clustering and reduce stability.

### 3.2 Scaling
We standardized numeric features (e.g., via `StandardScaler`) so that features with larger numeric ranges do not dominate clustering distance computations.

### 3.3 PCA (Principal Component Analysis)
We applied PCA to:
- compress correlated variables into orthogonal components,
- reduce noise and dimensionality,
- preserve most variance needed for clustering.

Final PCA representation used for clustering retained **~13 components** (variance-preserving reduction).

### 3.4 Model Selection — Why K-Means
We selected **K-Means** because:
- the dataset is numeric and scaled,
- K-Means is efficient and explainable,
- centroids provide an intuitive “typical customer profile” per segment.

### 3.5 Choosing k (metrics + interpretability)
We evaluated k using:
- **Elbow / Inertia**
- **Silhouette Score**
- **Davies–Bouldin Index**
- **Calinski–Harabasz Score**

Final selection emphasized:
- **cluster separation quality**
- **segment actionability** (avoid overly broad k=2 and avoid micro-segments)

**Final k:** **k = 3**

**Why not k=2:** k=2 can score well on some metrics in overlapping/noisy data, but it often produces segments that are too broad for business actions (too few personas). After trimming + PCA, **k=3** provided clearer separation and more actionable segment strategy.

## 5) Validation (Statistical Test)

We performed **ANOVA** across clusters on key business variables to verify that:
- differences are statistically significant (p-values),
- and practically meaningful (effect size via **eta-squared**).

This supports that clusters reflect measurable behavioral differences.

## 8) Limitations

- Clustering is **unsupervised**: results depend on feature design and scaling.
- PCA improves stability but reduces direct interpretability of PCA axes; interpretation is done using original business features.
- Cluster metrics may favor smaller k (e.g., k=2) even when business requires richer segmentation.
